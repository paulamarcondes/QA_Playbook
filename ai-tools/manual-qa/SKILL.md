# Manual QA Skill

Use this skill for practical manual QA support.

---

## Principles

- Test based on risk, not volume.
- Focus on user value and business impact.
- Prefer clear scenarios over long click-by-click scripts.
- Use exploratory testing when human judgment adds value.
- Capture evidence that helps the team decide.
- Report bugs with technical context and impact.

---

## Requirement review checklist

- [ ] User value is clear.
- [ ] Acceptance criteria are testable.
- [ ] Risk level is defined.
- [ ] Data needs are clear.
- [ ] Environment needs are clear.
- [ ] Integrations or contracts are documented when relevant.
- [ ] Security and permissions are considered.
- [ ] Accessibility is considered for user-facing changes.
- [ ] Logs or observability needs are considered.

---

## Test design checklist

Include when relevant:

- positive scenarios;
- negative scenarios;
- boundary cases;
- role/permission scenarios;
- data variation;
- integration behavior;
- error handling;
- usability and accessibility;
- regression risk;
- exploratory notes;
- automation candidates.

---

## Bug report checklist

A useful bug report includes:

- clear title;
- environment;
- build/version;
- affected area;
- steps or trigger condition;
- expected result;
- actual result;
- evidence;
- logs, IDs, or payloads when relevant;
- severity, priority, and risk;
- user or business impact;
- suspected area if known.
